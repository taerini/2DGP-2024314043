# PRD — 소닉 애니메이션 뷰어

> 근거 자료: `PRE-PRD.md`, `sonic-sprite.png`, 강의 자료 `LEC 09 애니메이션 뷰어 제작 실습`, 이전 실습 `Labs/LEC08_Animation/animation_viewer.py`

## 1. 목표

`sonic-sprite.png` 스프라이트 시트에 있는 소닉의 모든 동작을 차례로 자동 재생하는 뷰어를 만든다.
각 동작은 5회 반복한 뒤 1초 정지하고 다음 동작으로 넘어가며, 마지막 동작이 끝나면 첫 동작부터 무한히 반복한다.

## 2. 개발 환경과 제약

| 항목       | 값                                                                       |
| ---------- | ------------------------------------------------------------------------ |
| 언어       | Python 3                                                                 |
| 라이브러리 | pico2d (그 외 외부 라이브러리 사용 금지)                                 |
| 파일       | `Labs/LEC09/sonic_animation_viewer.py` **단일 파일**             |
| 리소스     | `Labs/LEC09/sonic-sprite.png` (399 × 525, 배경 투명 RGBA)             |
| 캔버스     | 1200 × 600                                                              |
| 확대 배율  | 원본의**4배** (가장 큰 프레임 높이 45px → 180px, 화면 높이의 30%) |
| 실행 위치  | `Labs/LEC09` 폴더에서 `python sonic_animation_viewer.py`             |

- 프레임 좌표는 별도 JSON 파일 없이 소스 코드 안의 데이터로 둔다(단일 파일 조건).
- 스프라이트 시트에 원래 있는 그림만 사용하고, 이미지를 수정하지 않는다.

## 5. 기능 요구사항

### FR-1 창과 화면

- 1200 × 600 캔버스를 연다.
- 매 화면마다 `clear_canvas()` → 그리기 → `update_canvas()` 순서로 갱신한다.
- 화면 하단에 기준 지면 높이 `GROUND_Y = 100`을 두고, 모든 프레임의 **아래 변 중앙**을 `(x, GROUND_Y)`에 맞춰 그린다. 프레임마다 크기가 달라도 발이 같은 높이에 놓인다.

### FR-2 프레임 출력

- 프레임은 `clip_draw(left, bottom, w, h, x, y, w*4, h*4)`로 4배 확대해 그린다. 이때 `y = GROUND_Y + h*4/2`.
- 왼쪽으로 이동할 때는 `clip_composite_draw(..., 0, 'h', ...)`로 좌우 반전해 그린다(시트의 소닉은 모두 오른쪽을 본다).

### FR-3 동작 재생 순서

- 4장의 표 순서(1 → 10)대로 재생한다.
- 각 동작은 **5회 재생** 후 **1초 정지**하고 다음 동작으로 넘어간다.
- 10번째 동작의 정지가 끝나면 1번부터 다시 시작한다(무한 반복).
- 프레임 수가 다른 동작도 같은 코드로 처리한다(동작 데이터의 프레임 목록 길이를 사용).

### FR-4 재생 속도

- 프레임 전환은 **실제 경과 시간**(`get_time()`)으로 계산한다. 루프 지연(`delay`)이 바뀌어도 재생 속도는 변하지 않는다.
- 동작별 프레임 시간은 기본 0.1초로 하고, 빠른 동작은 짧게 둔다.

| 동작     | 프레임 시간(초) | 1회 재생 | 5회 재생 |
| -------- | --------------- | -------- | -------- |
| idle     | 0.12            | 1.32     | 6.6      |
| walk     | 0.08            | 0.96     | 4.8      |
| run      | 0.06            | 0.36     | 1.8      |
| spin     | 0.06            | 0.54     | 2.7      |
| jump     | 0.06            | 0.36     | 1.8      |
| dash     | 0.05            | 0.30     | 1.5      |
| peel_out | 0.05            | 0.30     | 1.5      |
| turn     | 0.12            | 0.96     | 4.8      |
| skid     | 0.08            | 0.64     | 3.2      |
| pose     | 0.15            | 0.60     | 3.0      |

한 순환은 재생 31.7초 + 정지 10초 = 약 41.7초.

### FR-5 중앙 고정 동작 (idle, spin, turn, pose)

- `x = 600`(화면 가로 중앙)에서 재생하고, 오른쪽을 바라본다.

### FR-6 이동 동작 (walk, run, jump, dash, peel_out, skid)

- 프레임 애니메이션과 **동시에** 화면 위치가 바뀐다. 프레임이 바뀌는 순간에만 움직이지 않고, 매 화면마다 `x += 방향 × 속도 × 경과시간`으로 이동한다.
- 동작이 시작될 때 `x = 600`, 방향은 오른쪽에서 시작한다.
- 확대된 프레임의 가장자리가 화면 양 끝(0, 1200)에 닿으면 방향을 반대로 바꾸고, 좌우 반전된 그림으로 그린다. 프레임이 화면 밖으로 나가지 않는다.

| 동작     | 속도(px/s) |
| -------- | ---------- |
| walk     | 200        |
| run      | 450        |
| jump     | 300        |
| dash     | 550        |
| peel_out | 650        |
| skid     | 250        |

### FR-7 점프 궤적 (jump)

- 1회 재생(6프레임, 0.36초) 동안 포물선 한 번을 그린다. 최고 높이는 160px.
- 높이 `h(t) = 4 × 160 × p × (1 - p)`, `p`는 1회 재생 안에서의 진행률(0~1). 매 회 시작과 끝에 지면 높이로 돌아온다.
- 가로 이동은 FR-6을 따른다.

### FR-8 정지 구간

- 5회 재생이 끝나면 1초 동안 **마지막 프레임, 마지막 위치, 마지막 방향**을 유지한 채 계속 화면을 그린다.
- 점프는 5회째 착지한 상태(지면 높이)에서 정지한다.
- 정지 중에도 이벤트를 처리한다(`delay(1.0)`처럼 1초 동안 멈추는 방식은 쓰지 않는다).

### FR-9 종료

- 창의 닫기 버튼(`SDL_QUIT`)이나 ESC 키로 언제든지 종료한다. 재생 중, 정지 중 모두 즉시 반응한다.
- 종료 시 `close_canvas()`를 호출한다.

### FR-10 표시 정보 (선택)

- 창 제목이나 화면 왼쪽 위에 현재 동작 이름과 반복 횟수(예: `walk 3/5`)를 표시할 수 있다. 구현 비용이 크면 생략한다.

## 6. 비기능 요구사항

- 메인 루프는 `delay(0.01)` 정도로 CPU 사용을 낮춘다. 재생 속도는 FR-4에 따라 시간 기준으로 계산한다.
- 동작을 추가하거나 빼려면 동작 데이터 목록만 고치면 되도록 데이터와 재생 로직을 분리한다.
- 변수와 함수 이름은 LEC08 `animation_viewer.py`의 관례(대문자 상수, 짧은 한국어 주석)를 따른다.

## 7. 코드 구조 (권장)

```
상수      WIDTH, HEIGHT, SCALE, GROUND_Y, REPEAT=5, PAUSE_TIME=1.0
데이터    ACTIONS = [ {name, frames:[(l,b,w,h)...], frame_time, speed, jump}, ... ]
상태      action_index, repeat_count, frame_index, x, direction, 상태(재생/정지), 시각 기록
함수      handle_events()   종료 이벤트 처리
          draw_frame(frame, x, y, direction)
          start_action(index)
          update(dt)        프레임·이동·점프·정지·다음 동작 전환
          draw()
메인      open_canvas → 루프(handle_events, update, draw, delay) → close_canvas
```

## 11. 검증 기록 (28단계)

검증 방법: 뷰어를 그대로 실행하면서 `update_canvas()` 시점의 상태 값(동작 번호, 프레임 번호, x, 방향, 정지 여부)을 기록하고, 지정 시각에 화면을 캡처했다. 종료 이벤트는 SDL 이벤트 큐에 직접 넣었다. 검증용 스크립트는 저장소에 포함하지 않는다.

| 항목 | 결과 |
|---|---|
| 프레임 좌표 | 10종 76프레임 모두 시트 안, 확인용 이미지에서 잘림·섞임 없음. idle 일부 프레임은 붙어 있는 이웃 스프라이트와 1px 경계를 공유하지만 잘라낸 영역 안에는 들어오지 않음 |
| 재생 순서 | idle → walk → run → spin → jump → dash → peel_out → turn → skid → pose → idle |
| 5회 재생 시간(초, 측정) | idle 6.61, walk 4.80, run 1.81, spin 2.71, jump 1.81, dash 1.51, peel_out 1.50, turn 4.80, skid 3.21, pose 3.01 (FR-4 표와 ±0.01초) |
| 정지 | 모든 동작 1.00~1.02초, 정지 중 x·프레임·방향 변화 없음, 점프 정지 화면의 공 아래 변이 y=100 |
| 순환 | idle 시작 0.67초 → 42.53초, 한 순환 41.85초 (계산값 41.7초) |
| 이동 범위 | 이동 동작 6종의 그려진 가로 범위가 모두 0~1200 안 (walk 548~1200, run 534~1200 등) |
| 방향 반전 | 화면 끝에서 direction 이 1 → -1 로 바뀌고 캡처에서 좌우 반전된 그림 확인 |

개발 중 발견해 고친 문제

- 21단계: 경계 검사 뒤 더 넓은 프레임으로 바뀌면서 walk가 오른쪽 끝을 1.2px 넘음 → 경계 검사를 프레임 전환 뒤로 옮김
- 21~22단계: 이동 방향이 다음 동작으로 이어져 run이 왼쪽으로 출발 → 23단계에서 동작 시작 시 방향 초기화
- 24단계: 5회째 점프가 끝난 순간 정지 화면에서 공이 공중(약 73px)에 떠 있음 → 25단계에서 정지 중 높이 0

남은 확인 사항

- 실제 키보드로 ESC를 누르는 시험과 사람이 창을 보며 움직임이 자연스러운지 판단하는 일은 아직 직접 하지 않았다.
- 동작 이름(4장)은 그림을 보고 붙인 것이다.
